# NIKKE PC 런처 점검/정리 도구 (비공식)

2026년 11월에 알려진 **NIKKE PC 런처 공급망 공격**의 흔적을 점검하고, 필요하면 정리하는 Windows용 도구입니다.

> **비공식 도구입니다.** Level Infinite, Shift Up, Tencent와 무관하며 결과를 보증하지 않습니다.
> 근거는 공개 분석 보고서와 그 댓글 제보입니다: <https://gist.github.com/MotherSphere/d6c049a09ba8ac3085c51ee9df24a4e5>
> 정보가 계속 정정되고 있으니 보고서를 직접 확인하세요.

## 사건 요약
- 9월 27일, 런처가 불러오는 공식 CDN 자바스크립트 파일 4개가 변조되었습니다.
- 늦어도 10월 23일(GMT)부터 일부 실행에서, 런처가 열려 있는 동안 공격자가 명령 실행, 파일 열람, 스크린샷을 할 수 있는 원격 제어 에이전트가 내려갔습니다.
- Windows에서는 크롬이 로드하는 DLL이 추가로 설치되어 런처를 닫아도 계속 동작할 수 있습니다. 보고서의 코드 분석상 **크롬이 설치되어 있지 않아도 설치될 수 있습니다.**
- 11월 3일 3개 파일은 교체되었지만, 일부 CDN 서버에서 변조본이 계속 나갔다는 제보가 있었습니다. 이미 감염된 PC는 복구되지 않습니다.

## 이 도구가 하는 것 / 하지 않는 것
**하는 것**
- 로컬 파일, 레지스트리, 캐시에서 알려진 흔적을 검색합니다 (기본은 읽기 전용).
- 정리 전에 증거(로그 등)를 바탕화면에 복사합니다.
- 항목마다 확인을 받은 뒤 악성 레지스트리 키, DLL 폴더, 런처 캐시, 임시 파일을 삭제합니다.
- 관리자 권한이 있으면 hosts 파일과 방화벽에 공격 도메인과 IP 차단을 추가합니다.

**하지 않는 것**
- 네트워크에 접속하지 않습니다. 공격자 서버에도 접속하지 않습니다.
- 파일, 로그, 자격증명을 외부로 보내지 않습니다.
- 악성 파일을 실행하지 않습니다.
- 비밀번호를 바꾸거나 세션을 로그아웃하거나 지갑 자산을 옮겨 주지 않습니다. 직접 해야 합니다 (아래 참고).

## 사용 방법
1. 이 폴더의 파일을 모두 같은 위치에 둡니다 (`NikkeLauncherCleanup.ps1`, `NikkeLauncherCleanupGUI.ps1`, `ioc.json`, `Run-GUI.bat`, `Run-CLI.bat`).
2. 인터넷에서 받은 파일이면 PowerShell에서 한 번 실행합니다: `Get-ChildItem . | Unblock-File`
3. **NIKKE 런처를 완전히 종료**합니다 (트레이 아이콘 포함).
4. 다음 중 하나로 실행합니다.
   - **GUI:** `Run-GUI.bat` 더블클릭
   - **콘솔:** `Run-CLI.bat` 더블클릭
   - 직접 실행: `powershell -NoProfile -ExecutionPolicy Bypass -File .\NikkeLauncherCleanup.ps1`
5. 먼저 **점검만**을 실행해 결과를 확인하고, 필요할 때 **점검 + 정리**를 실행하세요.
6. hosts/방화벽 차단까지 하려면 관리자 권한이 필요합니다. GUI의 "관리자 권한으로 다시 실행" 버튼을 쓰거나 관리자 PowerShell에서 실행하세요.

NIKKE 폴더를 자동으로 찾지 못하면 GUI의 폴더 입력란, 또는 `-NikkePath "D:\Games\NIKKE"` 옵션을 쓰세요.

## 점검 항목
| 항목 | 의미 |
|---|---|
| `debug.log`의 `k2f_chan`, `agent started as` | 에이전트가 실행됨 (가장 확실한 신호) |
| `%APPDATA%\nikke_launcher\tbs_cache\Local Storage\leveldb`의 `k2f.agent` | 에이전트가 실행됨 (NIKKE 폴더를 지워도 남음) |
| `HKCU\...\CLSID\{E77CC89B-7401-4C04-8CED-149DB35ADD04}` | 크롬 persistence가 설치됨 |
| `Chrome\User Data\PlatformExperienceHelper\<64자리 hex>\platform_experience_helper.dll` | 위와 동일 |
| 코드 캐시의 `insightjs.com/l.js` | 로더만 실행됨 (페이로드 수신 여부는 별개) |
| HTTP 캐시의 변조 파일 ETag | 변조된 파일을 받았음 (보조 신호) |
| `%TEMP%\k2f*` | 에이전트가 쓴 임시 파일 |

**오탐 주의:** `PlatformExperienceHelper` 폴더 자체, `LoadFeatures` 파일, `onominan.tmp`, HKLM의 같은 CLSID는 정상입니다. 이 도구는 건드리지 않습니다.

## 정리 순서 (코드로 강제)
1. 증거 백업 (바탕화면)
2. HKCU CLSID 키 삭제
3. 64자리 hex 폴더 삭제. DLL이 잠겨 있으면 **재부팅 후 자동 삭제**를 예약합니다. 이 스크립트 파일을 이동하거나 지우지 마세요.
4. `%TEMP%\k2f*` 삭제
5. `tbs_cache` 삭제
6. hosts와 방화벽 차단 (관리자)

레지스트리 키를 먼저 지워야 하는 이유는, 키가 남아 있으면 크롬이 DLL을 다시 로드해 폴더를 지울 수 없기 때문입니다.

## 결과 해석과 한계
- **"흔적 없음"은 "감염되지 않음"의 증명이 아닙니다.** NIKKE 폴더를 삭제했거나 재설치했다면 로그가 없습니다. 압축된 `.ldb` 안은 검사하지 못합니다.
- Defender 오프라인 검사가 크롬 DLL을 탐지하지 못했다는 제보가 있습니다. 백신 결과만 믿지 마세요.
- 에이전트의 명령 실행 기록은 런처 로그에 남지 않아서, **무엇이 유출되었는지는 알 수 없습니다.**
- Linux/Steam Deck(Proton)은 지원하지 않습니다. Proton에서도 영향을 받을 수 있으니 홈 폴더의 비밀 정보를 점검하세요.
- 실제 감염된 PC에서의 충분한 테스트를 거치지 않았습니다. 중요한 PC라면 삭제 전에 백업하고, 에이전트 실행 흔적이 있으면 **Windows 재설치**가 가장 확실합니다.

## 감염 흔적이 있다면 직접 해야 할 일
1. **깨끗한 다른 기기**(휴대폰 등)에서 비밀번호 변경: NIKKE/Level Infinite → 이메일 → 디스코드 → 은행 → 브라우저에 저장된 모든 비밀번호
2. 모든 서비스에서 세션 로그아웃과 2단계 인증 활성화 (쿠키는 비밀번호 없이도 악용될 수 있음)
3. GitHub, npm, AWS, AI 서비스 API 키, SSH 키 등 개발자 자격증명 폐기 후 재발급
4. 크롬에 암호화폐 지갑 확장이 있었다면 **새 지갑과 새 시드 문구**로 자산 이전
5. 공식 수정이 발표되기 전까지 NIKKE PC 런처를 실행하지 마세요.

## IOC 갱신
탐지 규칙은 `ioc.json`에 분리되어 있습니다. 새 도메인, IP, 파일 해시가 보고되면 이 파일만 수정하면 됩니다 (`ioc.json`이 없으면 스크립트에 내장된 기본값을 씁니다).

## 신뢰 확인
- 스크립트는 평문이므로 실행 전에 직접 읽어 보세요. 외부 접속 코드가 없다는 것을 확인할 수 있습니다.
- 배포본의 해시: `Get-FileHash .\NikkeLauncherCleanup.ps1 -Algorithm SHA256`
- 출처가 불분명한 사본을 받았다면 원본 저장소와 해시를 비교하세요.
